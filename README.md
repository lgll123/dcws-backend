问题1：通过低代码平台系统设计生成的代码如何运用到目标系统中？
低代码平台与目标系统可以是不同的运行时实例，目标系统可以以低代码平台为基础，裁剪所需的功能。低代码平台不包括代码构建和部署能力，低代码平台产生的代码需要开发人员手工添加到对应的目标系统中。需注意的是生成的代码需要基础技术底座的支撑，若目标系统和低代码平台的技术底座有区别，产生的代码可能会有问题。

问题2：通过低代码平台系统设计生成的代码已经在目标系统中稳定运行了，并且在这个过程中已经在之前的基础上添加了很多业务逻辑，后续又想通过低代码系统进行页面逻辑修改，如何实现？
低代码平台只支持从0到1生成代码的过程，目标是提高效率。后续代码修改，在IDE中进行，不在低代码平台的范畴内。对于通用或标准的业务逻辑，系统支持自定义代码模版，包括前端页面模版和后端代码模版，开发人员可以按照模版的规则配置添加自己想要的模版，然后一键生成对应的业务代码，导入到自己的系统中。

问题3：前端开发过程中有不同的岗位角色，如UI设计岗和前端开发岗。不同的角色如何相互配合使用前端设计器？如果UI设计产出的样式风格与前端设计器生成的前端代码的样式风格不一致怎么办？
1. 低代码平台使用了业界主流的设计体系，目前支持 Element Plus，后续计划支持阿里的 Ant design、Facebook的Mui组件库等，达到更多样化的选择。建议在开发过程中，UI设计人员以主流UI体系为准进行设计，这样前端设计器产生的代码可以与UI设计适配。
2. 若UI设计与代码设计器产生的代码有差异，需要人工做差异化比对。低代码平台负责从0到1，提升效率。开发人员继续与UI设计的要求比对，修改差异，满足个性化需求。
3. 针对大客户，我们可以根据提供的设计图样式修改前端设计器定制化前端组件模板（工作量较大）。
